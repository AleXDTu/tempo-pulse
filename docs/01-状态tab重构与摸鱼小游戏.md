## 起因

现在应用对「状态切换」的反应分三档：休息弹休息屏、认真/摸鱼有结束前预告，而自定义状态只有一条系统通知（engine.rs:382-402 硬编码文案），主窗口本身没有任何动静——通知一闪而过，人不在屏幕前就错过了。同时摸鱼时间没有随手的消遣：想看微信读书/小红书要自己去开浏览器，想玩把小游戏更是无从谈起。

这轮要解决的问题：

1. 自定义状态切换时，应用要主动、扎眼地把用户拽回来——窗口震动、结算画面级别的特效，每个状态自己配。
2. 状态 tab 成为摸鱼的一站式入口：一键打开微信读书/小红书的独立窗口，一键打开一个像素射击小游戏。
3. 状态 tab 现在是「类型说明卡 + 平铺状态卡」，要容纳特效配置和摸鱼入口，结构得重排。

## 用户定下的方向

2026-11-12 拍板：

1. BGM 由用户自己提供音频文件，项目里留明确的加载点，不使用商业游戏原曲。
2. 游戏素材用 Kenney 的 CC0 素材库：候选 Pixel Platformer（18×18 瓦片、约 200 文件）、Pixel Platformer Blocks（约 80 文件）、Pixel Shmup（16×16 射击向、约 128 文件）。敌人、背景、瓦片由开发会话挑；主角各状态图片由用户另外提供，代码里留好替换点。
3. 微信读书/小红书参考 tw93/Pake 的实现：Tauri 用系统 WebView 打开远程站点，不用 iframe（两站有 X-Frame-Options 限制）。应用内新开 webview 窗口，同时留一个用系统浏览器打开的入口。Tauri 2 的 capability 配置要对远程 origin 单独授权。
4. 加强版通知的作用范围是自定义状态：每个自定义状态单独开关、单独选特效（主体窗口震动、类似蜘蛛 Win 结算画面的特效等，可以叠加）。
5. 实施方式：三个功能各分独立 worktree（task 的 isolated 参数），按难易程度排序分期。
6. 方案整体确认，按三期串行实施（加强版通知 → 摸鱼网页入口 → 像素射击游戏）。
7. 老板键 ⌘⇧H 一并覆盖新增窗口：第 2 期的微信读书/小红书窗、第 3 期的游戏窗都跟着隐藏、跟着恢复，各自在当期顺手实现。
8. 游戏背景用程序化生成的夜间城市剪影（Kenney 只用于瓦片、敌人、子弹和主角占位），与第 2 条「素材用 Kenney」在背景这一项上偏离，按本条为准。
9. 自定义状态特效只在「进入该状态块」时触发，块结束不触发。

## 目标和不做的事

### 目标

1. 配置了特效的自定义状态到点切换时，主窗口无论当时是显示还是隐藏，都会被带到用户眼前并播放所选特效（震动/结算画面，可叠加），用户不需要做任何操作就能注意到。
2. 状态 tab 的摸鱼区里一键打开微信读书或小红书的独立应用内窗口，登录一次后 Cookie 留存（重开免登录）；同一位置也提供用系统浏览器打开的入口。
3. 状态 tab 一键打开 960×540 的像素射击游戏弹窗，能完整玩一局：跳跃、5 个角度射击、前后上下入场的敌人、碰撞受伤、计分重开，背景是多层视差的夜间城市屋顶；关掉游戏窗口后计时不受任何影响。
4. 用户把自己的 BGM 音频文件和主角各状态图片放进应用数据目录的约定位置后，下次打开游戏即自动生效，不需要改代码、不需要重新构建。

### 不做的事

1. 不用 iframe 嵌微信读书/小红书：两站的 X-Frame-Options 会拦，已拍板走系统 WebView 独立窗口。
2. 不内置任何商业游戏原曲和素材：BGM 与主角图由用户提供，其余素材全部 Kenney CC0，版权干净。
3. 不做 Pake 那种站点级增强（UA 定制、快捷键注入、广告过滤、多标签）：这轮只要「能打开、能登录、能复用」，增强另开一轮。
4. 不给远程站点开放任何 Tauri IPC 权限：远程页面拿不到本机能力，安全边界保持最紧。
5. 不做游戏多关卡、存档、成就、道具、双人：第一版单场景无尽模式，玩过再决定加什么。
6. 不做特效参数编辑器（时长/幅度/密度调节）：第一版每种特效一个固定档，先看效果。
7. 不动认真/摸鱼/休息三类的现有反应（休息屏、结束预告、⌘⇧H 掩护）：这轮只给自定义状态加特效，已稳定的行为不改。
8. 不在托盘和全局快捷键加新入口：入口统一放状态 tab，托盘入口以后再说。
9. 不做 Windows 平台的专项验证：手头只有 macOS 开发机；震动用的是跨平台窗口 API（set_position），Windows 行为上线后按用户反馈调。

## 需求分档

### 必须有

1. 自定义状态特效配置：每个自定义状态卡上有特效总开关和特效多选（震动、结算画面），随状态一起保存；总开关关掉时保留所选组合，重新打开即恢复播放。
   - 验收：状态 tab 里新建一个自定义状态，打开特效总开关，勾选「窗口震动」和「结算画面」两项，点保存；重启应用后两项勾选和总开关状态都在；再把总开关关掉保存，重启后勾选组合仍保留。
2. 特效触发：进入配置了特效的自定义状态块时，主窗先确保可见再依次播放全部所选特效。
   - 验收：在时间表里把某自定义状态块的开始时间改到约 1 分钟后保存（不动机器时钟，走的就是同一条切换路径），按 ⌘⇧M 把主窗藏起来；到点后主窗自动出现，窗口本体左右震动约半秒，随后全窗播放结算粒子动画约 3 秒后自动消失。
3. 特效叠加与独立：多个特效同时配置时全部播放；系统通知开关（设置里的通知）与特效互不影响。
   - 验收：同一个状态同时配震动和结算画面，到点两者都播；设置里关掉「系统通知」后特效照播。
4. 特效扩展机制：新增一种特效只需加一个类型枚举值和一个播放器实现，数据结构不用迁移。
   - 验收：分两半——脚本可验：配置 UI 的特效选项以 `src/lib/effects.ts` 注册表为唯一来源，StatesView 里 grep 不到硬编码的选项数组；页面必验：开发期临时注册一个试验类型，配置区选项自动出现该项、移除注册后选项消失。
5. 摸鱼区（状态 tab 新分区）：含微信读书、小红书两个入口，每个入口两种打开方式（应用内窗口/系统浏览器）。
   - 验收：状态 tab 可见「摸鱼」分区；点「微信读书 · 应用内」打开独立窗口加载 weread.qq.com，能扫码登录；关闭窗口后再点一次，窗口重新打开且仍是登录态（Cookie 留存）；点「浏览器打开」调起系统默认浏览器。
6. 窗口复用：应用内入口已开时再点不重复开新窗，而是聚焦已有窗口。
   - 验收：微信读书窗口已开时再点入口，不出现第二个微信读书窗口，已有窗口置前。
7. 游戏入口与窗口：摸鱼区一键打开 960×540 游戏弹窗，窗口可拖动、可关闭，关闭即销毁。
   - 验收：点「摸鱼小游戏」入口弹出游戏窗；玩的过程中主窗计时正常走（迷你窗倒计时不受影响）；关游戏窗后主窗无报错，再点入口能重新打开。
8. 核心玩法：主角 x 轴固定、世界向左滚动；y 轴跳跃踩平台；机枪在面朝方向的半平面内 5 个角度（平射/斜上/正上/斜下/正下）可切换，面朝方向可前后切换；至少 4 种入场模式的敌人（右侧地面、右侧飞行、上方空降、左侧后方突袭）；子弹与敌人、敌人与主角、主角与平台三组碰撞；血量、无敌帧、死亡结算与重开。
   - 验收：实际玩一局：能跳上/跳过平台间隙；按方向键能在 5 个角度间切换弹道并用左右键转身打到后方敌人；四种敌人都出现过；被打中掉血且有闪烁无敌帧；血量耗尽出现结算画面显示分数，点重开能再来一局。
9. 视差夜景：天空、月亮（极缓慢移动）、云层、两层城市楼群（速度不同）、近景屋顶平台（游戏速度）至少六个层次，从后往前速度递增。
   - 验收：目测游戏画面：月亮几乎不动，楼群慢速左移且远层比近层更慢，屋顶平台以游戏速度左移，层次感能一眼分辨。
10. BGM 加载点：应用数据目录 `game/` 下放用户自己的音频文件即自动作为 BGM 播放，没有则静音不报错；状态 tab 摸鱼区提供「打开游戏资源目录」入口。
    - 验收：把任意 mp3 改名为约定文件名放进 `~/Library/Application Support/com.evanft.tempo-pulse/game/`，打开游戏后 BGM 循环播放；删掉文件后打开游戏无报错、无声。

    - 验收：放入约定的站立/跑动/跳跃图后打开游戏，主角显示为用户图；清空目录后恢复占位图，无报错。
12. 素材合规：仓库内游戏素材全部来自 Kenney CC0 或程序化生成，主角占位图与正式替换机制隔离。
    - 验收：脚本可验——`src/assets/game/` 下每个子目录的来源在 README 表格中登记，grep 不到任何商业游戏素材名。

### 最好有

1. 特效预览：配置特效时点「预览」立即播一次，不用等时间块到点。
   - 验收：状态卡上点预览按钮，立刻看到所选特效完整播放一遍。

3. 难度递增与最高分：击杀计分，生成间隔随时间缩短，死亡结算显示最高分（本次安装内）。
   - 验收：连续玩 2 分钟，敌人出现明显变密；死亡画面显示本局分数与历史最高分。

### 以后再说

1. 摸鱼区自定义任意网站（用户自己加 URL、起名）——设计上 Rust 白名单表已参数化，加站点是改一张表。
2. 更多特效类型（彩带、闪光、自定义图片粒子、音效特效）——特效注册表机制已留路。
3. 游戏内容扩展（关卡、道具、Boss、双打）——游戏逻辑独立成 `src/game/` 模块，窗口层只挂载，扩展不碰窗口架构。
4. 游戏窗口置顶开关、等比缩放、记住位置。
5. 特效参数化（时长/幅度配置）与按状态的更多通知定制（标题/文案模板）。
6. 远程站点窗口的站点级增强（UA、快捷键、广告过滤，Pake 的高阶玩法）。

## 方案

先说三个贯穿性的设计决策，再按功能展开。

### 决策一：特效引擎放前端，Rust 只做窗口物理操作

- **方案 A（推荐）**：特效播放器全部在主窗前端（Vue 特效层 + Canvas 粒子），Rust 只提供一个 `shake_main_window` 命令做窗口本体的物理震动（循环 set_position 抖动后复位）。
  - 好处：动画能力（粒子、缓动、motion-v）都在 WebView 里，开发调试快；特效层是普通 Vue 组件，随主窗生灭，没有额外窗口管理。
  - 代价：需要 Rust 加一个震动命令（约几十行）。
  - 适合：特效作用对象是主窗口本身——本轮需求正是如此。
- **方案 B**：特效做成独立透明置顶窗口（照 rest 屏模式），全屏结算动画盖在所有应用上。
  - 好处：特效不受主窗尺寸/可见性约束，能做全屏冲击。
  - 代价：多一个窗口页面和生命周期管理，动画照样要在 WebView 里画，复杂度明显更高。
  - 适合：以后要做「盖满全屏的强提醒」时再启用。
- **推荐 A**。理由：特效的目标是「把主窗带到眼前并引人注意」，A 直接达成；B 解决的是这轮不存在的问题。

### 决策二：游戏做成独立 Tauri 窗口 + 自写 Canvas 循环

- **形态**：
  - **方案 A（推荐）**：独立游戏窗口（label `game`，960×540，无边框自绘顶栏），新 html 入口 `game.html`，照 `create_rest`（windows.rs:78）的现成模式创建。
    - 好处：尺寸独立于主窗、关闭即销毁不占主窗状态、与现有「一个 html 一个窗口」的三窗架构完全一致（情报-2 §3）；玩的时候主窗可以藏起来（配 ⌘⇧H），更像「弹窗小游戏」。
    - 代价：vite 加一个入口、capabilities 的 windows 数组加一个 label。
  - **方案 B**：主窗内浮层（StatesView 或 App 层挂一个全屏 div）。
    - 好处：不碰 Rust 和 vite 配置。
    - 代价：受主窗 980×720 限制、与 tab 状态纠缠（切 tab 游戏怎么办）、主窗被 boss key 藏掉游戏就没了。
  - **推荐 A**，代价是复制一个已经很成熟的模式。
- **引擎**：
  - **方案 A（推荐）**：自写 Canvas 2D 游戏循环（fixed timestep 更新 + requestAnimationFrame 渲染）+ AABB 碰撞。
    - 好处：这个游戏的机制面很窄——单场景、无瓦片地图编辑、直线弹道、矩形碰撞，教科书级代码量（估千行级）；对「主角 x 固定 + 世界滚动、5 角度弹道、六层视差」这种高度定制的机制，引擎抽象层帮不上忙反而挡路；零新依赖，Vue 窗口卸载时销毁干净。
    - 代价：循环、碰撞、对象池要自己写自己调。
    - 适合：单场景迷你游戏，正是本轮。
  - **方案 B**：引入 Phaser 3。
    - 好处：输入/物理/补间/分组现成，bundle 加约 1MB（桌面应用不算负担）。
    - 代价：学习与集成成本（Vue 生命周期挂接、像素风配置）；本项目定制机制多，Phaser 的大头（场景管理、瓦片地图、arcade 物理）用不上多少。
    - 适合：以后要扩成多关卡、瓦片地图、复杂物理时再迁移。
  - **推荐 A**；如果第 3 期开工前评估发现机制膨胀（比如要加 Boss 战和行为树），再换 B，接口按「窗口层只认 start/destroy」设计，迁移面可控。

### 决策三：远程入口用 Rust 侧白名单命令开窗口，远程页面零权限

- **方案 A（推荐）**：Rust 常量表登记站点（id → 名称/URL/尺寸），命令 `open_web_entry(id)`：窗口已存在则聚焦，否则 `WebviewWindowBuilder::new(app, label, WebviewUrl::External(url))` 创建。远程窗口的 label 不加入任何 capability 的 windows 数组——Tauri 2 里不授权就没有任何 IPC 权限，远程页面摸不到本机能力。浏览器入口用已装的 `tauri-plugin-opener`（opener:default 已授权，capabilities/default.json）。
  - 好处：URL 白名单在 Rust 里，前端传不了任意地址；权限边界最紧；生命周期（复用/聚焦/销毁）集中一处。
  - 代价：加站点要改 Rust 常量表（对个人应用是小事）。
- **方案 B**：JS 侧 `new WebviewWindow(url)` 动态开。
  - 好处：不动 Rust。
  - 代价：前端要拿 `core:webview` 相关权限；白名单只能靠前端自觉；窗口生命周期散在 Vue 里。
- **推荐 A**。

### 功能一：加强版通知（自定义状态特效）

**数据模型**（前后端同步改，types.ts:1-2 与 model.rs:2 注释要求一一对应）：

```ts
// src/lib/types.ts
export type StateEffectType = "shake" | "finale"; // 以后加类型只动这里和播放器注册表
export interface PulseState {
  id: string;
  label: string;
  emoji: string | null;
  color: string;
  kind: StateKind;
  /** 特效总开关（「单独开关」的载体）：关掉时保留所选组合但到点不播。仅对 custom 类型生效 */
  effects_enabled?: boolean;
  /** 进入该状态块时播放的特效；空数组 = 没选特效。仅对 custom 类型生效 */
  effects?: StateEffectType[];
}
```

Rust 侧 `model.rs` 的 `PulseState` 加两个字段：`#[serde(default = "default_true")] pub effects_enabled: bool`（特效总开关，照 model.rs:211-213 的 default fn 模式）和 `#[serde(default)] pub effects: Vec<String>`（旧配置自动补空数组），并照 model.rs:361-378 加旧配置反序列化测试。特效配置走现有 `save_states` 全量保存通道，不加新命令。

**特效注册表与播放**：

- `src/lib/effects.ts`：`EFFECT_DEFS: Record<StateEffectType, { label: string; play(ctx: EffectContext): Promise<void> }>` 注册表。`EffectContext` 提供 `invoke`、状态（emoji/颜色）、特效层挂载点。新特效 = 加枚举值 + 注册一个播放器，配置 UI 从注册表渲染选项（满足「必须有」第 4 条）。
- `src/components/effects/FinaleOverlay.vue`：结算特效，全窗 Canvas 粒子——以状态色/emoji 生成的卡片从顶部撒落、重力弹跳、渐次淡出（蜘蛛纸牌 Win 结算的观感），约 3 秒，点击可提前结束。
- 震动播放器：`invoke("shake_main_window")`；窗口可见性由触发编排层统一保证，播放器只管自己的效果。
- 触发点：`App.vue` watch pulse store 已有的 `lastTransition`（pulse.ts:14 本来就注释「用于窗口做闪烁动画」，目前无消费者）。命中 `to.state.kind === "custom"`、特效总开关开启且 `effects` 非空时，先 `invoke("show_main_window")`（commands.rs:81-83 已有，show + unminimize + set_focus，幂等）把主窗带到眼前，再依次播放所选特效——「确保可见」放在触发编排层，只配结算画面这类不含震动的组合时主窗同样会被带出来。注册表里不存在的特效名直接跳过不报错（effects 在 Rust 侧是字符串数组，手改配置的笔误不该让播放崩溃）。系统通知仍由 Rust 照发（engine.rs:382-402 不动），两者独立。

**Rust 震动命令**（commands.rs，注册进 lib.rs:105 的 invoke_handler 数组）：

`shake_main_window(duration_ms, amplitude)`：取主窗当前 outer_position，spawn 线程按正弦衰减在原位附近循环 set_position，结束后精确复位。时长第一版固定 600ms、幅度 6px（播放器侧传参，命令不内置固定数值）。Tauri 2 没有官方 shake API（tauri-plugin-notification 的权限表里只有通知本体，情报-3 §3、§4），set_position 循环是可行路径；Windows 上高频 set_position 有重绘闪烁的可能但未实测，本轮只在 macOS 验证（「不做的事」第 9 条）。

**状态 tab 重排**（StatesView.vue）：

- 「状态类型与反应」说明卡：custom 一栏文案从「仅切换通知」改为「切换通知 + 可配置特效（震动/结算画面）」，其余三类不动。
- 状态卡片：custom 类型的卡片在反应说明行下方展开「进入时特效」配置区——开头一个特效总开关（「单独开关」的载体，临时全关不丢所选组合），下面每种特效一个自绘 checkbox（复用 base.css 已有自绘 checkbox 方案，情报-1 §6）+ 一个「预览」小按钮（最好有档）；非 custom 卡片不显示该区。
- 底部保存条沿用现有 dirty/校验/保存逻辑，特效选择随 `saveStates` 一起走。

**游戏逻辑层**（`src/game/` 新目录，窗口层只认 `start(canvas)` / `destroy()`）：

- 逻辑分辨率 480×270（16:9），画布整数倍放大到 960×540，`image-rendering: pixelated`；瓦片基准 18px（Kenney Pixel Platformer），逻辑高 270 = 15 瓦片，各层坐标取整到像素网格。
- 循环：fixed timestep 60Hz 更新 + rAF 渲染，增量钳制防后台回来跳帧；子弹/敌人/粒子对象池。
- 分层渲染（后往前）：夜空渐变 + 星星 → 大月亮（极缓慢漂移）→ 云层（慢）→ 远景楼群（程序化剪影，慢）→ 近景楼群（程序化剪影 + 亮窗点阵，中速）→ 屋顶平台（游戏速度，Kenney 瓦片拼装）→ 敌人/子弹/主角 → 偶发前景装饰（天线/广告牌剪影，略快于平台）→ HUD（分数/血量/角度指示）。
  - 楼群用程序化生成：高度随机的矩形楼 + 少量亮窗，零素材、可随 seed 变化，夜景剪影比贴图更贴气质；瓦片、敌人、子弹用 Kenney 包。这里与「用户定下的方向」第 2 条有一处偏离要说清楚：拍板写「背景由开发会话从 Kenney 挑」，但 Pixel Platformer 自带的 backgrounds 是通用平台关卡背景，没有夜间城市楼群（情报-3 §5）；程序化剪影更贴魂斗罗三代屋顶夜战的参考画面，所以背景推荐程序化生成、Kenney 用于瓦片/敌人/子弹/主角占位。要严格照拍板条目走，换回 Kenney backgrounds 只是替换两个渲染层的素材来源，结构不变（列为「没定的问题」第 4 条）。
- 主角：x 固定在屏幕宽 1/3 处，y 由跳跃/重力决定；踩平台（AABB 落在平台顶面）；掉出屏幕底部扣血并在最近平台重生（短暂无敌帧）。跑动动画按世界滚动速度驱动。
- 射击：机枪连发，5 个角度 = 面向半平面的 {平射, 斜上 45°, 正上 90°, 斜下 -45°, 正下 -90°}，上/下键在 5 档间循环切换（或直接 5 键位，开发会话按手感定），左右键切换面朝方向（镜像弹道），HUD 显示当前角度。
- 敌人 4 类（参数化：速度/血量/生成权重）：右侧地面爬行（沿平台）、右侧飞行（高度正弦逼近）、上方空降（垂直落向主角附近）、左侧后方突袭（低空快速）。生成间隔随时间缩短（最好有档的难度递增）。
- 碰撞：子弹×敌人（AABB）、敌人×主角（受伤 + 无敌帧 + 击退敌人）、主角×平台（单向踩踏，从下方穿过）。
- 死亡：血量归零 → 结算画面（本局分数/最高分/重开按钮）。
- 输入：键盘（方向/WASD + 射击键），Esc 暂停菜单；窗口失焦自动暂停（blur 事件）。

**音频与素材管线**：

- BGM：应用数据目录 `game/bgm.mp3|m4a|wav`（第一个匹配的；不收 ogg——macOS 的 WKWebView 对 Ogg Vorbis 支持不完整，收了会出现「无声又说不清是格式问题还是加载点坏了」的排查困难），游戏启动时经 `convertFileSrc` 加载（assetProtocol 已开放 $APPCONFIG/**，tauri.conf.json:28-34，RestApp 背景图同款通道，情报-1 §8）；无文件则静音。加载点集中在 `src/game/audio.ts` 一处，常量写明约定文件名。摸鱼区放「打开游戏资源目录」按钮（Rust 照 `open_config_dir` 模式加 `open_game_dir`，顺带建目录）。

## 验证

不设第 0 期基线验收：本轮全部是新增功能，没有「改前改后可比对的数字」（改前表现就是「什么都没有」），基线记录没有意义。

### 第 1 期（加强版通知）

1. 旧配置兼容（脚本可验，会话 A 交验收脚本）：验的是 effects 和 effects_enabled 字段向后兼容。用旧格式 config.json（无这两个字段）跑 `cargo test`（含新增旧配置反序列化用例）+ 启动应用读配置。通过标准：测试全绿、启动后自定义状态 effects 为空、effects_enabled 为 true，不报错。改前表现：无此字段，新代码直接崩溃或丢配置。

## 没定的问题

1. 特效只在「进入自定义状态块」时触发；块结束时要不要也来一次收尾特效？——该用户回答。不卡开工：第一版只做进入时，加结束触发是注册表加一个触发点的小改动。
2. 游戏窗口固定 960×540；要不要支持拖拽放大（画布等比缩放）？——该用户回答。不卡开工：第一版固定，`start(canvas)` 接口不假设尺寸，后补缩放不用重构。
3. 微信读书/小红书窗口要不要记住上次大小和位置？——该用户回答。不卡开工：第一版固定 1200×800 居中，位置记忆照 mini 窗模式后补即可。
